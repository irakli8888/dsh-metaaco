# Постоянные инструкции AI-агентам — dsh-metaaco

## Назначение и источники истины

Создаём адаптивную оркестрацию задач программирования: категоризация задачи,
выбор стратегии, ролей и дорогих/дешёвых LLM по времени, проверяемому качеству
и стоимости; сохранение удачных и неудачных исполнений и повторное использование опыта.

Читайте [архитектуру](docs/architecture.md), [реальный MetaACO](docs/metaaco-algorithm.md)
и [инфраструктуру](docs/infrastructure.md) перед проектированием изменений.
Фактический код текущей ревизии важнее исторических описаний. Документы различают
проверенное состояние, сведения владельца и целевые компоненты. При расхождении
обновите статус с указанием commit/даты; не объявляйте план реализованным.

## Порядок разработки

1. Strategy Bank/Registry: версии стратегий, задачи, попытки, ошибки, артефакты.
2. Независимый TDD Evaluator.
3. Metrics Collector.
4. Task Analyzer / классификация.
5. Strategy Selector с contextual UCB.
6. DAG Executor и явная передача артефактов через DeepSeek Harness.
7. Интеграция и развитие существующего MetaACO Optimizer.
8. Feedback и обновление политик на проверенных исходах.

Перед каждым этапом проверьте другие ветки/PR: не дублируйте уже выполненную работу.
В проверенной локальной ветке `codex/strategy-bank` банк уже есть; в базе этого
документа `main@08e0a1e` его нет. Это снимок на 2026-10-25, не вечный статус.
Первый этап этой задачи — документация. Масштабную переработку кода не начинать.

## Обязательные ограничения

- Работайте в отдельной ветке, создавайте PR; main напрямую не менять и PR автоматически не сливать.
- Сохраняйте публичные интерфейсы, форматы планов и поведение preview, отмены,
  остановки зависимых стадий и `dispose()`. Новые возможности вводите версионированно.
- Не выполняйте платных API-вызовов без отдельного разрешения и бюджета.
  Эта задача такого разрешения не даёт. `runWorkflow()` — низкоуровневый путь без
  собственного consent gate; не вызывайте его с реальным провайдером при проверках.
- Не создавайте новый ACO взамен существующего. Сначала изучите доступный код
  `/Users/iraklijkvacahia/PycharmProjects/metaACOwithCodex` и интерфейсы в профильном документе.
  Если путь недоступен, сообщите это; не добавляйте фиктивный fallback.
- Сохраняйте многоколониальность, выбор UCB, репликацию, элитный архив,
  мутации `alpha/beta/rho/q0/ls_iters/ls_prob` и локальный поиск.
- Элитный архив расписаний не равен постоянному Strategy Bank. UCB колоний не равен contextual UCB стратегий.
- Не меняйте SSH, firewall, portproxy, Tailscale и задачу Windows.
  Не угадывайте IP, пароли, ключи; секреты и сырые чувствительные промпты не коммитить.
- Недоступность Mac/сервера, пропущенные проверки и неподтверждённые версии
  явно отмечайте. Установленное ПО не означает проверенную совместимость.

## Качество, метрики, обучение

- Для изменений поведения: RED (целевой тест падает по ожидаемой причине до патча)
  → GREEN → REFACTOR с повторным запуском обязательных и регрессионных тестов.
  Для документации достаточно проверки фактов, ссылок и отсутствия runtime-изменений.
- Исполнитель не может единолично оценивать свой результат. Независимый evaluator
  использует закреплённые acceptance criteria и тесты, сохраняет команды, exit codes,
  хеши наборов тестов и логи по фазам. Ошибка среды не считается корректным RED.
- `completed` Harness не означает успешное решение. Пропуск тестов не означает GREEN;
  отсутствующее доказательство означает `inconclusive`, а не успех.
- Сохраняйте failed, timeout, cancelled, interrupted и inconclusive попытки,
  промежуточные расходы и причины. Не удаляйте неудобные результаты.
- Прогнозы времени/качества/стоимости храните отдельно от измерений; неизвестное —
  `null` с причиной, не ноль. API-cost по токенам и тарифу — расчёт, не подтверждённый счёт провайдера.
- Следуйте протоколу воспроизводимости и семи baseline в архитектуре. Разделяйте
  train/validation/test; не обучайтесь на исходах отложенного теста.

## Проверки перед PR

Из корня репозитория, без реальных LLM:

```sh
pnpm test
pnpm test:integration
METAACO_SOURCE=/Users/iraklijkvacahia/PycharmProjects/metaACOwithCodex python3 -B -m unittest discover -s python -v
git diff --check
```

Сначала убедитесь, что integration остаётся offline в текущей версии. В main этой
базы два integration-сценария используют опубликованный engine с offline-провайдером;
пропуски любых проверок фиксируйте отдельно.
Если runtime отсутствует в PATH, используйте доступный установленный runtime;
не устанавливайте зависимости и не запускайте длительные эксперименты автоматически.
В PR сообщайте: что изменено, что проверено, что пропущено, реальные ограничения доступа.
