# ADR 0012: прогноз стоимости, тарифный резерв и начальная допустимость

Дата: 2026-11-21. Основание: инфраструктурный пилот `c02135a`,
[отчёт](../research/webhook-pilot-results.md). Это новая версия подготовки job,
не изменение протокола завершённого пилота. Банк не обучался на его исходах.

## Решение

`prepareScenarioJob` создаёт job schemaVersion=2. `prices` сохраняет прежнюю
проверенную адаптером верхнюю тарифную границу API-вызова. Новое поле `forecasts`
хранит отдельный неизмеренный prior: inputTokens равен UTF-8 byte length исходного
описания +1024, outputTokens=4096. Стоимость prior рассчитывается по закреплённому
тарифу без кеш-скидки. Размер будущих parent artifacts и реальное поведение модели
не известны; prior не является точным tokenizer или гарантией расходов. Прогноз
10s/node также не измерен. Каталог и Selector теперь используют именно forecast,
а не сумму максимально возможных резервов всех вызовов. Usage/actual cost остаются
в самостоятельных измеренных полях. Job v1 сохраняет прежний путь стоимости.

Резервация денег выполняется прежним бюджетным адаптером перед каждым реальным
вызовом. Верхнюю границу нельзя заменить приблизительным числом токенов:
[провайдер прямо называет tokenizer-расчёт оценкой](https://api-docs.deepseek.com/quick_start/token_usage/).
Расход уточняется по полному usage; при сбое резерв удерживается. Если даже один
резерв не помещается в бюджет попытки, модель исключается до поиска с отдельной
причиной в `planned.catalogFilter`, а прямой запрос получает диагностический
отчёт без запуска evaluator/провайдера. Это известная невозможность безопасного
финансирования при текущем контракте, а не предсказание качества. Pro по-прежнему
требует резерв 1352441 microunits и при разрешении $1 не исполняется. Для него
нужен отдельный достаточный разрешённый бюджет либо обоснованная новая граница;
оба условия не создаются этой доработкой автоматически.

В `plan_skill_graph` появился opt-in `ensure_feasible_start` (JSON
`ensureFeasibleStart`). Он включён для scenario job v2; default существующих
stock/cold-start интерфейсов не меняется. Для минимальных разрешённых layout
выбираются самые дешёвые по каталогу назначения, необязательные роли пропускаются,
mandatory-роли и обязательный design компонент сохраняются. Структурных кандидатов
не более двух; их число записано в `initialization.structuralStartsConsidered`.
Это предварительное сравнение сумм каталожных стоимостей, не проверка качества
или полный RCPSP objective.

Выбранная перестановка передаётся в ту же `colony.sgs.generate` с callback целевой
функции. Полноценная оценка занимает **одну из 100**, видна первой в trace и
категории budget counts `initialization`. Только допустимый кандидат инициализирует
best первой колонии, элитный архив и небольшой феромонный след. Затем работают
обычные колонии, UCB, репликация, мутации и локальный поиск. Если лучшая каталожная
минимальная структура недопустима, она не объявляется успехом; поиск сохраняет
право закончиться ошибкой. Нет гарантии глобального оптимума, качества решения
или выполнения всех возможных ресурсов произвольного пользовательского каталога.
Это детерминированная инициализация настоящего MetaACO, не fallback вместо него.

`runScenarioJob` сохраняет прежнее поведение исключений и добавляет
`error.scenarioReport`, а также report.json schemaVersion=2. Новая обёртка
`runScenarioTrial` возвращает этот отчёт и при ошибке подготовки/выбора, чтобы
study driver не открывал отсутствующий ledger. Consent, ранняя отмена и ошибки
создания эксклюзивного каталога остаются исключениями без выдуманной попытки.
У отчёта есть `state`, `attempt` (null до beginAttempt), `error.phase/message`
и `accounting` с ledgerCreated/spentMicrounits/heldMicrounits/coverageComplete.
Доказанное отсутствие вызова runtime даёт ноль расходов; вызванный runtime без
доказательств учёта даёт null, а не ноль. При существующем ledger сохраняется
удержанный резерв. Невыполненные тесты не превращаются в успешную приёмку.
CLI использует эту обёртку и ставит exit code 1, если acceptance не подтверждена.

Промпт перечисляет неизменяемые .md-файлы и требует копировать их дословно.
Валидатор по-прежнему отклоняет любые изменения спецификации. Это уточнение
инструкции, а не гарантия, что модель всегда ей последует.

## Проверка и последствия

RED воспроизведён для отсутствующих initialization/trial интерфейсов и неявного
перечня immutable files; затем GREEN и регрессии. Проверяются исходный редкий
бюджетный случай seed 7, улучшение исходного seed колониями, общий cap при budget=1,
невозможный каталог, components при бюджете 987446 с реальными Harness/LlmRuntime
и synthetic API, отказ Pro до dispatch и удержание резерва при network error.
Платных повторов нет; научные таблицы старого пилота не меняются. Перед новыми
платными вызовами нужен новый закреплённый протокол, учитывающий opt-in initialization,
новые priors и бюджетные ограничения моделей.
