# ADR 0002: независимая фазовая оценка на закреплённых тестах

Дата: 2026-10-25. Следует принятой архитектуре и AGENTS.md; второй этап реализует локальный Node adapter, а не универсальный sandbox.

## Решение

Отделить authoring/execution Harness от решения об успехе. TDDEvaluator фиксирует TestSpec, запускает свои тестовые subprocess на текстовых snapshot и хранит приватную evidence. Внешние TestReport не являются входом положительного решения. При подключении Bank spec сверяется с immutable request, базовый revision — с baseCommit. Сессия резервируется уникальным event, чтобы другая сессия не подменила результат той же попытки.

Фазовые результаты не удаляются. Повторный GREEN допускается; evaluator оценивает последний GREEN и последний REFACTOR, сохраняя неудачи для будущих метрик/feedback. Baseline нужен для регрессий, RED — для точных именованных ERR_ASSERTION в закреплённом target suite на baseline snapshot. Остальные фазы исполняют все suite. Отдельный correctness signal позволяет хранить рабочий патч без подтверждённого TDD как inconclusive.

Запускается process.execPath с фиксированным reporter и аргументами, без shell и без наследования API-ключей/NODE_OPTIONS. Timeout/abort останавливают процессную группу на POSIX и ожидают close до cleanup. Output ограничен байтами, Node heap — 128 MiB. Временные рабочие копии создаются отдельно для каждого suite. Файлы тестов и источников сравниваются после запуска; изменение входов запрещает GREEN. Такой post-check не заменяет OS isolation против враждебного кода.

Node считает пустой тестовый файл или process.exit(0) успешно пройденным file-level test. Такой результат фильтруется и запрещается использовать как correctness evidence. Skipped/todo и отсутствие ожидаемых target имён также не считаются GREEN. Ошибка импорта не является ожидаемым assertion RED.

## Совместимость и ограничения

Новый API экспортируется как dsh-metaaco/evaluation; существующие index.js/planner.js и v1/v2 планов не меняются. Bank принимает EvaluationResult v2, при этом его старый низкоуровневый v1 остаётся совместимым и не превращается в independent evaluator. Полный Metrics Collector ещё не реализован, а durationMs здесь относится к subprocess suite, не ко всей задаче.

Первый adapter работает с Node built-in test runner и текстовыми manifest. Поддержка пользовательского checkout, зависимостей, Python/JVM, скрытого OS-защищённого набора и безопасного исполнения недоверенного кода требует отдельных adapters. Не устанавливаем ПО и не меняем серверные настройки. Хеши гарантируют идентичность переданных данных, а не подлинность строковых Git revisions или хронологии работы автора вне evaluator.

## TDD evidence разработки

Сначала создан runner, способный реально запускать тесты, и fail-closed evaluator без правила положительного решения. Затем 10 сценариев запущены до реализации фазового решения: 8 упали на целевых assertion (inconclusive вместо требуемого success/failed/correctness, отсутствие pin/order validation), 2 проверки неполной evidence прошли. Это поведенческий RED; ошибка импорта не использовалась как доказательство.

После фазовой логики прошли все 10. Дополнительные regression tests обнаружили ложный GREEN при изменении теста на диске и при нулевом количестве зарегистрированных тестов. Оба теста сначала упали на фактическом passed вместо неполной оценки; после integrity check и исключения синтетических file-level passes проходят. Ещё один поведенческий RED обнаружил повторное использование предыдущего success при сбое подготовки нового финального snapshot: теперь ошибочная фаза сохраняется и блокирует success. Всего 13 сценариев включают реальные subprocess, assertion RED, GREEN/refactor, регрессию, import error, пропуски, timeout, mid-flight abort, output cap, snapshot/spec tampering, порядок и сохранение собственных отчётов в Bank.
