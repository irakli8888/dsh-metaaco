# ADR 0013: редактируемые файлы и явные ответы ролей

Дата: 2026-11-21. Основание — [повторный пилот](../research/webhook-pilot-v2-results.md)
на fbea6c9: newline README остановил Fixed, design вернул лишний type, Pro и
MetaACO реализовали async handle вместо существующего синхронного API.
Это новый контракт будущих запусков, не переоценка завершённых попыток.

## Версии и совместимость

`webhookScenario()` и CLI без нового флага сохраняют webhook-retry-v2 и прежний
строгий Snapshot {revision,files}. Для новых запусков явно выбирается
`webhookScenario({version:3})` либо `--scenario-version 3`.
Новая задача webhook-retry-v3 включает доверенную host-конфигурацию:

```json
{"responseContract":{"schemaVersion":2,"readOnlyFiles":["README.md"]}}
```

prepareScenarioJob для этого контракта выдаёт job schemaVersion=3. DAG v3,
внутренний Snapshot, существующий Harness, отмена/dispose и денежные лимиты
не меняются. Неизвестная версия responseContract не переключается на legacy:
она отклоняется до model dispatch. Каждый readOnlyFiles путь должен быть
безопасным, уникальным и существовать в закреплённом исходном снимке.
Список задаёт host, модель его не формирует. Это универсальный механизм,
не правило для всех Markdown-файлов или только для webhook README.

## Wire-ответы модели

Design возвращает один JSON-объект с components непосредственно:

```json
{"schemaVersion":2,"kind":"architecture","revision":"design-1","components":[{"id":"a","files":["app.cjs"],"contract":"Chosen public entrypoint and agreed private interfaces"}]}
```

Это пример формы одного элемента, не готовая архитектура: реальный ответ обязан
покрыть все slot IDs из конфигурации (в текущем каталоге a/b/c), назначить
непересекающиеся .cjs-файлы и явно определить интерфейсы. Host проверяет эти
условия и создаёт прежний внутренний Snapshot с architecture.json, содержащим
schemaVersion=1/components. Дочерние исполнители и интеграция получают тот же
проверенный артефакт, что раньше. Модель больше не кодирует JSON архитектуры
внутрь строкового files["architecture.json"].

Реализация, интеграция, рефакторинг и заметки возвращают:

```json
{"schemaVersion":2,"kind":"files","revision":"code-1","files":{"app.cjs":"full generated source"}}
```

Каждой роли передаётся явный discriminator и JSON Schema с запретом лишних полей.
Промпт объясняет, что schema — описание, её type/properties не являются ответом.
Схема проверяется host-кодом; API по-прежнему получает JSON-object mode.
Гарантия provider-side constrained generation не заявляется.

Компонент возвращает ровно назначенные файлы. Реализация/интеграция/рефакторинг
возвращают полный снимок редактируемых исходников и новых файлов. Заметки ограничены
своим analysis.md/review.md/test-plan.md. Paths traversal, контрольные тесты,
пересечение владения, пропуск существующего editable source и неизвестные поля
отклоняются. Существующие read-only .cjs нельзя назначать компонентам.

## Сборка и доказательства

Модель не возвращает read-only файлы. Если она всё же прислала их, host отклоняет
ответ, а не принимает скрытое изменение. Для итоговых source Snapshot host добавляет
исходные bytes из baseSnapshot. Поэтому newline README не зависит от копирования
моделью: спецификацию передают один раз на вход, затем host восстанавливает её
точно. Read-only restoration не применяется к частичным компонентам и заметкам.
Исходный программный код не переписывается, не форматируется и не исправляется
нормализатором. Файл с неверной логикой всё равно должен провалить независимые тесты.

Сырые ответы сохраняются в scenario-output-N до валидации, успешная нормализованная
форма — в scenario-normalized-N с тем же N. Далее Harness сохраняет привязанный к
узлу dag-output и evaluator оценивает именно этот Snapshot. Для invalid response
raw остаётся, normalized не создаётся. Не смешивать эти доказательства: wire DTO
и исполняемый снимок имеют разные хеши и назначение.

## Публичный API и проверка

В README v3 явно сказано, что createApi и handle синхронны: handle возвращает
обычный {status,body}, никогда Promise/thenable. Асинхронны runOnce и sender.
Это уточнение существующего совместимого интерфейса, не навязывание приватной
архитектуры. Код target/regression suites не меняется относительно v2; меняются
id и метаданные явной спецификации. Независимая регрессия на калибровочном async
мутанте всё ещё падает. Host не превращает async-функцию в sync и не unwrap-ит Promise.

RED → GREEN покрывает новый контракт, readonly restore, запрет изменений README,
архитектурный DTO, владение файлами, invalid versions и async mutant. Все пять
режимов проверяются с typed synthetic responses через настоящий Harness и
независимые тесты; при TEST_EVALUATION_IMAGE они используют закреплённый Docker.
Это проверка инфраструктуры, не новые платные успехи моделей. JSON schema/prompt
не гарантируют, что реальная модель никогда не ошибётся в формате или реализации.
Для следующей платной серии нужны отдельный новый протокол и разрешённый бюджет.
