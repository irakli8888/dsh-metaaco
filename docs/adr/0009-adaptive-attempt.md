# ADR 0009: явный цикл попытки и admission на границе adapter

Дата: 2026-11-14. Реализация в feature-ветке поверх `ff7a574`.

Проблема: отдельные компоненты позволяли исполнить DAG без независимой проверки
перед зависимой стадией, а события usage приходят слишком поздно для admission.

Решение: runAdaptiveAttempt связывает закреплённый Feedback/Selector с binding
плана, evaluator, DAG, metrics и новым Feedback ref. Необязательный verifyArtifact
в DAG держит узел running до завершения проверки; отвергнутый output сохраняется,
но потомки блокируются. Старые вызовы без callback сохраняют поведение.

Budget wrapper устанавливается доверенным приложением на границе LlmAdapter,
включая prepared dispatch. Он резервирует гарантированный upper bound перед
stream и консервативно удерживает неизвестные расходы. Не подменяем bound
прогнозом, не перехватываем post-hoc events для разрешения уже выполненного вызова.
Существующий ledger обеспечивает атомарность без новой миграции.

Factory runtime остаётся доверенной точкой интеграции: только приложение знает
provider credentials, output caps, hidden retry policy и инструменты. Поэтому
наличие wrapper не аттестует все сетевые вызовы и не даёт coverageComplete=true.
MetaACO подключается через существующую проверку результата и сохраняет свой
алгоритм. Solver и selector overhead отделены от времени исполнения попытки.

Следствия: требуется отдельный runtime и корректный quote для каждого провайдера;
произвольный SDK нельзя объявить совместимым без проверки. Неудачи, частичные
измерения и независимые evidence сохраняются; ошибка cleanup не становится
success. Интерфейсы и границы: [adaptive attempt](../adaptive-attempt.md).
