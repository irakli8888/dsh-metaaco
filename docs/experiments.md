# Воспроизводимое сравнение семи подходов

Состояние 2026-11-14: ветка `codex/reproducible-experiments` от
`main@b896095`, после разрешённого слияния PR #12–15. Реализован frozen held-out
runner и отдельный offline launcher. Настоящие оплачиваемые эксперименты не
проводились. Синтетические результаты проверяют протокол, не превосходство моделей.

## Режимы

Все режимы получают одинаковые candidates, policy, test criteria и frozen Feedback.
Фильтрация моделей, инструментов, concurrency и ограничений прогнозов общая.
Недопустимая стратегия не выбирается даже для fixed baseline.

| Режим | Выбор маршрута | Планирование | Использование train-исходов |
|---|---|---|---|
| random | равномерный псевдослучайный выбор допустимого arm по seed | исходный DAG | нет |
| fixed | заранее закреплённый fixedArmId | исходный DAG | нет |
| cheapest | минимальный известный прогноз стоимости в валюте policy | исходный DAG | нет |
| historical-best | максимальная средняя награда совместимых train-попыток | исходный DAG | да |
| contextual-bandit | существующий disjoint LinUCB | исходный DAG | да |
| metaaco-without-bank | тот же fixedArmId | настоящий внешний MetaACO | нет |
| metaaco-with-bank | тот же contextual LinUCB | тот же настоящий MetaACO | да |

«Без банка» означает без использования прошлых исходов при выборе, а не без
журналирования попытки. Внутренний элитный архив MetaACO в обоих режимах включён;
многоколониальность, UCB, репликация, мутации и local search не изменены.
Solver по-прежнему оптимизирует Cmax, не многокритериальное назначение LLM.

Historical best совместим по категории задачи (bugfix/feature/…), точному arm и
policy; использует прежние правила reward с независимой оценкой и измерениями.
Неизвестные rewards исключаются, провалы учитываются. Если наблюдений нет ни для
одного допустимого arm, cold start — первый arm в каноническом порядке, отмеченный
в decision. Неизвестный arm не получает вымышленную среднюю награду 0, позволяющую
победить реально наблюдённый отрицательный исход. При равенстве — канонический порядок.

Selector принимает дополнительный `method`: `{kind:'random', seed}`, `{kind:'fixed',
armId}`, `{kind:'cheapest'}`, `{kind:'historical-best'}` либо существующий default
`{kind:'contextual-bandit'}`. Алгоритмы честно именуются в decision; baseline не
маскируется под LinUCB. Их привязанные исходы могут позднее использоваться в train.
Random использует SHA-256 и rejection sampling без modulo bias. Указанное 1/N —
вероятность равномерного алгоритма, не стохастическая вероятность при уже фиксированном
seed. Это не готовая оценка propensity для off-policy статистики.

## API

`dsh-metaaco/experiments` экспортирует `prepareExperiment`, `runExperiment`,
`summarizeExperiment`, `experimentMethod` и EXPERIMENT_MODES.

```js
const ref = await prepareExperiment(bank, {
  experimentId, feedback, seeds: [7, 11], fixedArmId, candidates,
  tasks, runtimeConfig, solverSource,
})
const result = await runExperiment(bank, ref, {
  journal: '/absolute/new-runs.jsonl', runtimeConfig, solverSource,
  python: 'python3', createRuntime, allowLlm: true, signal,
})
```

Подготовка не вызывает моделей или solver. Требует 2–32 различных uint32 seeds,
1–64 задачи, frozen Feedback. Каждая задача обязана входить в его test split,
а train/validation исключены. Запись задачи: `{request, baseSnapshot, bindings,
durations}`; durations сопоставляет armId с `{taskId: positiveIntegerSeconds}`
для всех узлов соответствующего DAG. Binding каждой кандидатной стратегии
обязателен и проверяется до первого dispatch.

Manifest хранится как неизменяемый artifact Bank: inputs, policy через feedback ref,
история train, тесты/исходники/prompts, модели/конфигурация runtime, seeds, fixed arm,
порядок запусков, commit, Node version, хеши lockfile/package, всех src JS и Python,
всех Python-файлов внешнего rcpsp. Исходники незакоммиченной реализации также
идентифицированы хешами. RuntimeConfig должен включать закреплённые тарифы,
конфигурацию провайдера/моделей и идентификатор реализации factory **без секретов**.
Он проверяется на равенство при запуске, но доверенность кода factory этим не
аттестуется. Содержимое manifest может быть чувствительным: храните Bank приватно.

Все семь режимов используют одинаковые пары task/seed. Порядок режимов внутри
каждой пары детерминированно перемешивается Fisher–Yates. Порядок задач канонический;
запуски последовательны, чтобы конкурентные эксперименты не делили незаявленные
ресурсы. Размер серии заранее конечен. Необходимость отдельного бюджета на реальный
API сохраняется: allowLlm — технический gate, а не разрешение владельца.

MetaACO запускается новым Python-процессом с тем же seed и существующим лимитом
100 оценок. Его вход/выход проверяются существующим контрактом; результат содержит
версию Python, параметры и хеши загруженных модулей. Несовпадение source не включает
fallback. Bridge invocation имеет дополнительный safety timeout 30 секунд.
Policy.maxWallTimeMs ограничивает всю ячейку: выбор, solver, исполнение и оценку;
timeout сохраняется отдельно от отмены. Общий лимит расходов серии не вводится:
он состоит из заранее известных per-attempt квот; caller отдельно контролирует
разрешённый совокупный бюджет. Поставщик/runtime обязан соблюдать signal и budget
adapter контракт из [adaptive-attempt.md](adaptive-attempt.md).

## Долговечность и отчёт

JSONL journal создаётся эксклюзивно (`wx`, права 0600), каждая запись синхронизируется
на диск. Сначала manifest ref, затем start/result каждой ячейки, затем summary.
Попытки используют стабильные ID из manifest hash и индекса. Наличие попыток этой
серии запрещает повторный запуск; оплачиваемого resume/retry нет. При аварии start
без result остаётся доказательством незавершённого запуска, а не успехом: проверять
Bank и выполнять interrupted recovery явно. Один manifest/journal имеет одного
владельца; параллельный запуск одной серии не поддерживается.

Результаты сохраняют failed, timeout, cancelled, inconclusive, ошибки до создания
попытки (`error`), неподходящие задачи (`inadmissible`), остаток после отмены
(`not-run`) и существующую running попытку после исключения (`unresolved`).
Metrics artifacts и Bank сохраняют наблюдаемые промежуточные расходы. Ошибка
journal/Bank может оборвать серию; уже выполненные вызовы не воспроизводятся автоматически.

Summary каждого режима содержит число запланированных строк, распределение состояний,
проверенные успехи и success rate (в знаменателе все строки, включая not-run),
median/p95/min/max фактического времени, известную расчётную стоимость, число
неизвестных полных расходов, полную стоимость и стоимость на успех. Quantiles —
nearest rank. Неизвестная полная стоимость не заменяется нулём: total и cost per
success остаются null. Известная сумма — только наблюдаемый subtotal, не счёт API.
Для time используются строки реально начатых ячеек; not-run имеет time=null.

Время ячейки включает selector/planner и adaptive attempt, но не первоначальную
подготовку manifest/проверку среды и не финальную запись отчёта. Их нельзя выдавать
за полный latency команды. Raw rows сохраняют пары task/seed для последующего
статистического анализа. Автоматические доверительные интервалы, тесты значимости
и вывод о победителе не вычисляются: требуется заранее выбранный метод с учётом
зависимости повторов внутри задач. Два seeds достаточны для smoke-протокола, не
для научного вывода об эффективности.

## Offline launcher

Из корня, с установленными зависимостями и доступным реальным внешним solver:

```sh
pnpm experiment:offline --source /path/to/metaACOwithCodex --out /new/output/directory
```

Команда запускает только локальный synthetic adapter: 2 независимых fixtures
(сложение/умножение), 2 seeds и 7 режимов, всего 28 коротких ячеек. Используются
реальные Harness/LlmRuntime и Node evaluator. «Хорошая»/«дешёвая» модели возвращают
заранее заданные кодовые snapshots; токены и тарифы искусственные, никакого API
нет. Встроенный elite solver настоящий; сравнение не подменяет его имитацией.

На выходе: приватный SQLite Bank/artifacts, manifest-ref.json, runs.jsonl,
report.json. Повторный запуск в ту же директорию не перезаписывает результаты.
Не коммитить эти каталоги. Собственный сетевой runtime подключается программным
API после отдельного разрешения и проверки реального provider adapter.

Для общего денежного лимита передайте runExperiment параметр seriesBudget
с полями budgetId (префикс series/), currency и limitMicrounits. Все попытки
в одном Bank используют один резервный журнал при одинаковом идентификаторе.
Лимит отдельной попытки продолжает действовать. Если двойное резервирование
прерывается после записи в общий журнал, резерв сохраняется до сверки.
