# Повторное сравнение с прямыми запросами

Версия stock-frozen-direct-v2, 21 ноября 2026. Новая серия сохраняет результаты
предыдущих экспериментов. Цель — сравнить оркестрацию с одним обычным запросом
на реализацию задачи, а также с informed fixed workflow.

## Условия

Девять методов: прежние семь и direct-flash/direct-pro. Пять seeds и пять
повторов дают максимум 225 исполнений. Первые семь используют прежний каталог
1836 маршрутов. Два прямых baseline являются отдельными условиями и не добавляются
в пространство выбора остальных методов. Каждый прямой baseline получает ровно
один узел implement без родителей. Промпт совпадает с описанием stock-reservation,
общий JSON формат ответа задаёт тот же runtime. Нет планировочного промпта,
ревью, обязательного рефакторинга или автоматического исправления ответа.

Один вызов является воспроизводимым приближением простого запроса пользователя,
а не моделью любого поведения человека. Отдельный обычный agent loop с исправлениями
после тестов потребует своего протокола и одинакового общего бюджета попыток.

Исходный код, acceptance tests, модели, max_tokens=1024, JSON-format, тарифы,
Docker и исходные прогнозы сохраняются. После контроля все девять методов
перезапускаются в новом общем временном окне, порядок исполнений перемешивается.
Нельзя добавить только прямые результаты к прошлой серии и объявить это полностью
парным сравнением. Общая история — те же 700 исходов с закреплённым hash; она
доступна только обученным методам. Все 45 решений выбираются до новых результатов.
Подготовка истории $1.169737 учитывается отдельно.

## Единая основная приёмка

Primary metric новой серии — correctness по закреплённым acceptance/regression
тестам на конечном артефакте. Полный TDD compliance показывается отдельно для всех
методов. Это явное изменение относительно основной метрики прошлой серии.
Прямой baseline проходит baseline, наблюдаемый RED и GREEN, но не получает
фиктивного REFACTOR. Independent evaluator сохраняет correctness=passed и
TDD=inconclusive, общий Bank state остаётся inconclusive при отсутствии полного
TDD. В новой исследовательской таблице это может быть acceptance success, но
никогда не называется TDD success. Production evaluator и его критерии не меняются.

Primary success требует независимого evaluator provenance, correctness=passed
и отсутствия ошибки исполнения. Если задача требует полного TDD как обязательного
условия, такая прямая попытка не проходит соответствующий TDD критерий. Эта серия
оценивает конечную корректность, а не отменяет требования других режимов проекта.

## Отчёт

Для всех девяти методов показываются acceptance success, исходный Bank state,
correctness, TDD compliance, время выбора, время исполнения, токены/вызовы, стоимость
и причины ошибок. Учитываются все вызовы, включая оборванные и ошибочные. Для прямого
baseline ожидается один вызов на попытку; неподтверждённые расходы остаются null.
Медианы успешных и всех попыток различаются явно. Fixed обозначается informed.
Код прямого исполнителя находится в src/experiments/direct-attempt.js.

## Запуск

Preview: node examples/run-stock-frozen.js --direct-baselines --source SOURCE.
Исполнение добавляет --execute --out NEW_ABSOLUTE_DIRECTORY. Контрольная серия
с --preflight использует девять методов по одному разу и хранится отдельно.
Основной режим имеет 45 решений и 225 исполнений. Исходный пул проверяется по
35 снимкам, SHA summary и configHash, результаты новой серии не меняют историю.

Офлайн проверяется однократный вызов direct, корректность без фиктивного TDD,
сохранение критерия старого режима, одинаковая история, изоляция repeat outcomes
и отсутствие direct-узлов в поисковом каталоге семи исходных методов.
Новая серия остаётся same-task пилотом. Перенос на новые задачи не проверяется.
