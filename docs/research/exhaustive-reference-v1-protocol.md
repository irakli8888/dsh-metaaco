# Exhaustive-reference-v1: план полного проверочного пространства

Дата: 23 ноября 2026, Europe/Samara. База: main@3a696b4 после слияния PR #28
по прямому запросу владельца. **Статус: проект протокола и проверенный подсчёт,
не запущенная серия.** Платных вызовов этого этапа нет. Task/test fixtures,
launcher и сравнение методов ещё предстоит реализовать через TDD. До их бесплатной
калибровки, фиксации commit/manifest и отдельного бюджета запуск запрещён.

## 1. Проверяемый вопрос

Насколько близко к эмпирически лучшим допустимым маршрутам приходит MetaACO
при ограниченном количестве реальных исполнений? Помогает ли постоянный Bank
по сравнению с тем же MetaACO без него и другими baseline?

Полный перебор здесь нужен **независимому проверяющему** как ориентир.
Его результаты не заполняют банк алгоритма перед cold-start сравнением.
Алгоритм получает только результаты собственных попыток. Накопленный ранее
банк multitask-training-v1 также не импортируется. Проверка переноса на новые
задачи — отдельная серия, не вывод из этого same-task эксперимента.

## 2. Какое пространство рассматриваем

Существующий decoder python/skill_decisions.py, без нового ACO. В каждом
активном навыке два ресурса: deepseek-flash или deepseek-v4-pro.
Два agent slot, не более двух одновременно работающих агентов.

- Monolith: implement → refactor.
- Components: обязательный design → три implement-a/b/c → integrate → refactor.
- analyze необязателен и предшествует design/implementation.
- design необязателен для monolith и обязателен для components.
- write-tests необязателен, получает тот же контекст, что implementation;
  при его наличии monolith тоже получает integrate перед дальнейшими стадиями.
- review необязателен, идёт после implementation/integrate, перед refactor.
- Каждый активный узел независимо получает Flash или Pro.

write-tests создаёт вспомогательный test plan; обязательные acceptance/regression
тесты всегда принадлежат независимому evaluator, а не этому агенту.
В components design выбирает внутренние файлы/контракты, но не публичные критерии.

Число определяется текущим decoder, а не историческим числом 1836:

| Семейство | Подсчёт активных назначений | Маршрутов |
|---|---|---:|
| Monolith | 2² × 3(analyze) × 3(design) × 3(review) × (1 + 2(write-tests) × 2(integrate)) | 540 |
| Components | 2(design) × 2³(implement) × 2(integrate) × 2(refactor) × 3(analyze) × 3(review) × 3(write-tests) | 1728 |
| Всего | | **2268** |

Три альтернативы означают skip / Flash / Pro. Декартово произведение всех групп
содержит 10368 сырых assignments: 1728 нарушают обязательный component design,
оставшиеся 8640 после исключения назначений неактивных узлов дают 2268 маршрутов.
Отклонение этих 1728 — нарушение структурного контракта, не предположение о качестве.

Идентичность маршрута: сортированный набор skill/provider/model/dependencies.
Перестановки независимых узлов не считаются разными маршрутами. Полный перебор
в этом протоколе **не означает перебор всех расписаний, промптов или архитектур кода**.
Для сравнения вводится единая детерминированная политика dispatch: готовые узлы
в лексикографическом порядке ID, два слота, запуск по завершению родителей.
Она должна применяться к reference и всем сравниваемым методам. Требуется отдельная
offline-проверка, что платный launcher действительно применяет её и сохраняет
original solver order отдельно; пока такой launcher не реализован.
Оптимальность относится только к закреплённым маршрутам при этой политике.

[Структурный аудит](data/exhaustive-reference-v1-space.json) получен
[analysis-only скриптом](data/enumerate-reference-space.py), который временно
подменяет search_workflow только в своём Python-процессе, чтобы перечислить
кандидатов **того же production decoder**. Solver и API не вызываются.
Synthetic cost=0/seconds=10 в этом аудите — технические поля для перебора,
не прогнозы качества, стоимости или времени. Хеши decoder и канонического
каталога закреплены. При изменении decoder число и hash пересчитываются до запуска.

В артефакте дополнительно есть ограниченный инфраструктурный срез 228 маршрутов
без analyze/write-tests. Это **не полное пространство серии** и не разрешение
заменить им 2268. Он подходит лишь для бесплатной проверки связности контрактов;
все 228 DAG прошли независимый JS validateDag. Платная серия использует full.

## 3. Задача и независимые критерии

Предлагается новая train-only задача document-store-reference-v1:
версионируемое in-memory хранилище JSON-документов с optimistic concurrency,
атомарными пакетами изменений и журналом операций. Это проект спецификации,
не существующий fixture и не утверждение о проверенных тестах.

Публичный контракт предстоит закрепить до dispatch:

- Синхронные чтение/создание/обновление/удаление; точные формы аргументов/ошибок.
- Compare-and-swap по версии, отсутствие изменений при stale version.
- Batch либо применяет все операции, либо не меняет документы/версии/журнал.
- Идемпотентный operation ID: повтор того же запроса не дублирует изменение;
  конфликт payload отклоняется с заранее определённым результатом.
- Независимые JSON-копии на входе/выходе, специальные строковые ключи,
  однозначные ограничения допустимых значений и числового переполнения.
- Журнал фиксирует только успешные изменения и имеет детерминированный порядок.
- Без внешней сети/пакетов; исходник CommonJS, host-owned readonly спецификация.

Для каждого пункта нужны acceptance tests, регрессии и независимый oracle;
контрольные мутации должны обнаруживать неатомарный batch, игнорирование версии,
повторное применение ID и утечку изменяемых ссылок. Калибровка:
baseline проходит, заготовка даёт ожидаемый assertion RED, oracle проходит
GREEN и REFACTOR. Ошибка среды не RED. Подготовленные тесты хешируются;
всем методам доступны одинаковые публичные требования, не source evaluator.
Эта задача не является held-out test и не выбирается по платным исходам серии.

## 4. Полный reference: измерить, не предсказать

Для каждого из 2268 маршрутов — **три заранее назначенных независимых исполнения**
с чистым исходником и отдельными artifact/attempt IDs: 6804 попытки максимум.
Повторы получают детерминированно перемешанный порядок route/repeat, закреплённый
до запуска. Cloud generation недетерминирована; solver seed не seed API.
Нельзя повторять лишь понравившихся лидеров и выдавать это за несмещённое сравнение.

На каждой попытке: pinned Docker, baseline → RED → GREEN → REFACTOR,
обязательные тесты/регрессии и полный учёт расходов. Failed, timeout, cancelled,
interrupted, inconclusive сохраняются. DTO-отказ — end-to-end неуспех,
логическая корректность полного исходника при этом может остаться неизвестной.
Расходы частичных попыток сохраняются. Ошибки среды отдельно от ошибок стратегии.

По каждому маршруту: число успехов/n, неопределённость доли, измеренные стоимости
и времена всех попыток и отдельно успешных. 3/3 не доказывает надёжность 100%.
Публикуется Парето-фронт наблюдавшихся успешных решений (cost/time), а не один
«гарантированно оптимальный» маршрут. Статистическое сравнение 2268 noisy кандидатов
по трём повторам не даёт доказательства истинного глобального оптимума.
В отчёте сохраняются доля покрытия каталога и причины незавершённых исполнений.
Если серия остановлена досрочно, нельзя объявлять весь reference измеренным.

## 5. Поиск с пустого банка и baseline

Отдельные пустые банки на метод/seed, никаких reference outcomes в их snapshots.
Семь обязательных условий: Random Strategy, Fixed Workflow, Cheapest Model,
Historical Best, Contextual Bandit, MetaACO without Bank, MetaACO + Bank.
Предлагаемая матрица: seeds 7/11/19/23/31 × 20 реальных попыток × 7 методов =
700 исполнений максимум; одинаковые спецификация, модели, лимиты и dispatch.

Fixed — заранее выбранный Flash implement → refactor, не победитель перебора.
Random равномерно выбирает уникальную route identity из full catalog.
Cheapest использует закреплённые тариф/token priors, не реальные reference cost.
Historical Best/Contextual Bandit видят лишь собственную sealed прошлую историю.
MetaACO + Bank получает лишь собственные qualityEvidence/memory seed;
MetaACO without Bank имеет пустую историю между попытками, сохраняя штатные
внутрипоисковые колонии/феромоны/элитный архив. В обоих случаях 100 локальных
оценок на поиск, включая повторные посещения и initialization.

До запуска фиксируются tie-breaks, initial exploration, UCB параметры,
reward, priors и правила повторного исполнения маршрута. Текущий сценарный launcher
не предоставляет все семь условий с единым контрактом, поэтому сравнение ещё
предстоит реализовать/проверить. Нельзя незаметно заменить один метод другим.
Повторные реальные попытки считаются в лимит 20; готовые исходы из кеша не
засчитываются как новое исполнение. Истории seed не смешиваются.

Основные метрики: число попыток/накопленная цена/время до первого полного успеха,
вероятность хотя бы одного успеха к попытке k, лучшее найденное успешное решение
при одинаковом ресурсе, стоимость приобретения опыта. Неуспешные seed имеют
цензурированное время до успеха, не ноль. Reference используется только при анализе
достигнутого фронта, не выборе действий. Такая same-task серия не доказывает перенос.

## 6. Объём и бюджет

У full catalog суммарно 16848 активных узлов за один проход, поровну Flash/Pro.
При трёх повторах максимум **50544 API-вызова** reference, если ни один DAG не
остановится раньше; ещё до 700 поисковых попыток идут отдельной частью.
Лимиты ответа/входа, timeout и тарификация закрепляются одинаково для всех методов.
План: существующие 8192 output/call, 32768 output/attempt, 262144 input bytes,
300s execution, отдельный 30s search; actual usage должен оставаться видимым.
Сумма лимитов попытки может останавливать длинные DAG: это одинаковое ресурсное
ограничение, которое требуется явно проверить до запуска и учитывать в исходах.

Средний расход прошлого multitask pilot: $0.349232 / 76 ≈ $0.004595 на вызов.
Механическая экстраполяция дала бы около **$77.42 за один reference проход,
$232.26 за три**. Это лишь ориентир по другой серии: длина контекста/выходов,
навыки и доля ранних отказов меняются, прогноз не является лимитом или обещанием.

Консервативные per-call reservations текущего адаптера при output 8192:
Flash 309831, Pro 1352441 USD microunits. Сумма этих bounds для всех 50544 вызовов
составляет $42008.937984; это заведомо грубый потолок admission, **не ожидаемый счёт
и не требуемый заранее заблокированный баланс**. Реальный series cap задаётся
отдельно, резервируются только активные вызовы и освобождаются settlement.
Прогноз расхода и hard bound хранятся раздельно.

Предыдущее разрешение $5 относилось к завершённым 24 попыткам; остаток не считается
автоматическим разрешением новой серии. Новый budget cap согласуется после бесплатных
проверок и фиксации launcher/manifest. Нет автоматического пополнения, paid retry
или переключения на сокращённое пространство при нехватке бюджета.

## 7. Ближайшая реализация и критерии готовности

1. TDD нового task fixture, oracle и mutation controls; одинаковые публичные prompts.
2. Versioned exhaustive launcher: полный catalog hash, 3 повтора, чистые snapshots,
   canonical dispatch, общий transactional ledger, fsync журнал, сохранение частичных
   исходов и безопасное продолжение без повторной оплаты завершённых attempt IDs.
3. RED/GREEN тесты против утечки reference/будущих/чужих seed outcomes;
   единый семиметодный launcher и зафиксированные policy settings.
4. Offline preview печатает 2268 routes, 6804 reference attempts, матрицу сравнения,
   рассчитанные bounds и требует explicit execution/budget. Без ключа не обращается к API.
5. На Lenovo — synthetic API + настоящий Docker, все роли/две модели, контроль
   byte-preserving normalization, cancellation/timeout/failed feedback и budget holds.
6. Закрепить source/archive/container/test/config hashes, проверить CI, запросить
   новый бюджет. Только после этого paid dispatch; не менять протокол по результатам.
7. Отчёт содержит измерения и неуспехи, coverage, Парето-фронт и ограничения;
   dossier обновляется независимо от того, подтвердится ли гипотеза.

Этот документ начинает этап с проверяемой постановки и полного подсчёта.
Готовность платного эксперимента им не заявляется.


## Проверка документационного этапа

Изменений production runtime нет. Подсчёт воспроизводится из существующего decoder;
проверены формулы, catalog hashes, ссылки и scientific verify_data.py. Локально
185 unit прошли, 36 Python прошли (один тест — сохранённая незакоммиченная правка
владельца и не входит в PR). Использован установленный Node v24.22.3.
Прямые команды node --test соответствуют package.json: pnpm wrapper пытался
автоматически проверить/переустановить зависимости и остановился до тестов;
установка не выполнялась, зависимости не менялись. Docker-проверка команды плагина
локально требует TEST_EVALUATION_IMAGE и отдельно отмечается как пропущенная.

Integration с METAACO_SOURCE: 41 passed, 1 Docker command test skipped; все вызовы
использовали offline/synthetic provider. Проверка исходного MetaACO доступна локально.
