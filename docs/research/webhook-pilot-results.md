## Назначение и условия

Проверить исполнимость нового сценария, реальные ответы моделей, изоляцию Docker,
учёт расходов и артефактов. Это не обучение, не оценка преимущества методов
и не основание для статистического вывода. Seed 7, по одной запланированной
попытке direct-flash, direct-pro, fixed, components, metaaco. История каждого
исполнения пуста; исходы предыдущих условий не используются для выбора следующего.
Накопленный stock-банк не подключён. В отдельные банки сохранены созданные попытки;
предшествующие beginAttempt отказы сохранены как диагностические файлы, а не
выдуманные исполнения стратегии. Между банками обратной связи нет.

Лимиты: 8192 выходных токена на вызов, 32768 на попытку, input 262144 bytes,
artifact 65536 bytes, 2 агентных слота, API timeout 120s, attempt timeout 300s.
Прогноз 10s/node — неизмеренный prior. Общий оставшийся бюджет передаётся каждой
последующей попытке: это защитный пилот, условия бюджетов поэтому не идентичны.
Протокол и исходные драйверы сохранены в data/webhook-pilot-v1/ и
[data/webhook-pilot-v1-summary.json](data/webhook-pilot-v1-summary.json).

## Бесплатные проверки

Шесть integration-проверок нового launcher с синтетическим API прошли на Lenovo.
Эти проверки сами используют локальный evaluator; отдельно перед платными вызовами
выполнена Docker-калибровка: baseline 2/2, RED 12 ожидаемых ERR_ASSERTION,
GREEN и REFACTOR по 12/12 target и 2/2 regression. Образ работает без сети,
с read-only filesystem, непривилегированным пользователем и лимитами ресурсов.
Эталон из test/fixtures применялся только при калибровке, не передавался реальной модели.

## Выявленные ограничения

1. Тарифная защита резервирует 1000000 входных токенов на каждый вызов независимо
   от фактического размера prompt. При max_tokens=8192 резерв Flash составляет
   309831 microunits, Pro — 1352441. Поэтому Pro при бюджете $1 блокируется,
   даже если ожидаемый реальный расход намного меньше. Резерв не является
   прогнозом фактической стоимости.
2. Selector использует сумму этих верхних границ как оценку полной стоимости
   маршрута. Шесть Flash-узлов components дают 1858986 microunits, больше
   оставшихся 987446. Это объясняет отказ до попытки. Нельзя считать его
   доказательством низкого качества декомпозиции или недостатка опыта.
3. MetaACO с seed 7 завершил локальный поиск ошибкой
   `No feasible choice found within the evaluation budget`. Это не доказательство
   отсутствия решения: минимальная implement → refactor с двумя Flash имеет
   границу 619662, ниже остатка 987446. Поиск не гарантирует нахождения такого
   кандидата при лимите 100 оценок. Успешный offline preview с большим бюджетом не
   гарантирует успеха при другом ограничении.
4. Изменение README моделью блокируется правильно, но текущая полная JSON-копия
   исходников создаёт дополнительную возможность ошибки. Перед новым протоколом
   следует уточнить сохранение неизменяемых файлов без ослабления acceptance.
5. Внешние пилотные драйверы не обработали отсутствие budget ledger до beginAttempt:
   первоначальный драйвер консервативно остановился, продолжение также завершилось
   ошибкой при чтении отсутствующего ledger. Исходные журналы сохранены. Отдельный
   аудит установил ноль попыток/событий/учётных записей у components и metaaco;
   отсутствие ledger здесь подтверждено отсутствием dispatch, а не принято за ноль
   наугад. Итоговый отчёт реконструирован без новых API-вызовов. Время MetaACO
   не измерено полностью и оставлено null с причиной.
