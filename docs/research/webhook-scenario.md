# Сценарий изменения сервиса доставки webhook

Актуальная версия webhook-retry-v2 подготовлена 21 ноября 2026. Она заменяет
неисполнявшийся вариант v1 из bbc8701, где авторы заранее задали четыре модуля,
store/claim/settle интерфейсы и владение файлами. Изменение произошло до модельных
запусков сценария. Старые материалы доступны через Git. Данные v1 и v2 смешивать нельзя.

## Короткое пользовательское задание

> Доработай webhook-сервис: добавь подписки и приём событий, идемпотентность,
> подпись сообщений, повторы при ошибках и конкурентную доставку без дублирования
> одновременно отправляемого сообщения. Сохрани существующее поведение и выполни
> внешнюю спецификацию из README.md. Внутреннюю архитектуру выбери самостоятельно.

Точный английский userBrief содержится в task.js. Он одинаков для direct Flash/Pro
и остальных методов. Им передаются одинаковые существующие файлы проекта.

## Общая спецификация

README.md описывает внешние требования, на которых основана приёмка.
Заданы маршруты /subscriptions и /events, форматы запросов/ответов, коды 201/202/400/409/404,
семантика идемпотентности, подписи, статусов доставки и повторов. Дано внешнее
createApi(options) → handle()/runOnce(), чтобы evaluator мог взаимодействовать
с реализацией без реальной сети. sender/clock внедряются для детерминированных
наблюдений. GET /health и version() остаются совместимыми.

Начальный проект содержит app.cjs и README.md. Внутренние файлы, структуры данных,
блокировки и приватные методы свободны. Можно написать решение в одном app.cjs
либо добавить модули. Требований создать store.cjs, worker.cjs или signature.cjs нет.
Конкретных методов claim/settle, последовательности изменения флагов или рецепта
синхронизации модель не получает. Конкурентная корректность проверяется наблюдением
отправок и статусов через публичный интерфейс.

Это минимальный in-memory MVP одного процесса с асинхронными worker-вызовами.
TCP-сервер, БД, восстановление после crash и exactly-once remote effects не входят
в обязательную приёмку. Оценка относится к изменению сервиса с фиксированным внешним
API, а не к свободному проектированию любого публичного API.

## Независимые проверки

Сохранены 12 target tests и две regression проверки.

1. Валидация подписок и повторного ID.
2. Валидация события и case-insensitive ключ идемпотентности.
3. Повторный запрос с переставленными вложенными JSON ключами без новых доставок.
4. Конфликты ключа и ID события.
5. Fan-out по подпискам на момент приёма события.
6. Изоляция входных данных и возвращаемых снимков.
7. HMAC фактических отправленных байтов, включая Unicode.
8. Успешная доставка один раз.
9. Повтор после исключения sender по внедрённым часам.
10. Исчерпание числа попыток после non-2xx.
11. Отсутствие двойной отправки при конкурентных runOnce().
12. Независимый прогресс получателей при сбое одного из них.

Тесты импортируют только публичный app.cjs. Состояние читается через GET /events/:id,
а результат доставки наблюдается через injected sender. Они не импортируют приватные
модули и не проверяют названия алгоритмов или расположение внутренних данных.
Регрессии сохраняют version/health и ответ 404. Подробные ожидания соответствуют
доступному всем методам README, а не скрытым функциональным требованиям.

Исходник v2 проходит регрессии, все 12 target tests падают по ожидаемым ERR_ASSERTION.
Модульный эталон проходит GREEN/REFACTOR. Однофайловый эталон без store/worker/signature
модулей проходит ту же приёмку и регрессии. Это две упаковки калибровочного кода,
а не независимые исследовательские LLM-решения. Мутации неверной подписи, двойной
отправки и слишком раннего повтора обнаружены соответствующими assertions.

Эталоны хранятся только в test/fixtures/webhook-reference.js. Они не входят в задачу,
README или модельные артефакты. Калибровка доказывает свойства тестового стенда,
а не успешность обучения или реальное TDD модели.

## Архитектура и параллельность

В v2 больше нет заранее назначенных компонентных файлов и гарантированных трёх
исполнителей. Если стратегия выбирает декомпозицию, архитектурный этап должен
сформировать внутренние интерфейсы, зависимости и непересекающиеся заявки на файлы.
Компонентные агенты получают именно этот артефакт, а интеграция проверяет совместимость.
Стоимость архитектурного этапа включается в стоимость соответствующего метода.

Launcher `examples/run-webhook-scenario.js` исполняет версионированный артефакт
`architecture.json`: `{schemaVersion:1,components:[{id,files,contract}]}`. В этой
конфигурации заданы три абстрактных слота a/b/c, но файлы, обязанности и приватные
интерфейсы выбирает модель на этапе design. Число компонент пока не оптимизируется.
Проверяются безопасные пути, непересекающееся владение и покрытие app.cjs.
Компонент возвращает ровно назначенные ему файлы. Интеграция получает design и все
компонентные результаты. MetaACO исключает декомпозицию без design как структурно
неисполнимую; это не предсказание провала тестов. Нынешний MetaACO выбирает
в пределах заданных альтернатив; сам по себе он не изобретает интерфейсы программных
модулей. Возможное число маршрутов v2 пока не закреплено, прежний расчёт 3132 для
фиксированной трёхкомпонентной схемы к нему не применяется.

Direct baseline самостоятельно выполняет архитектурные решения внутри одного
запроса. Дополнительный agent loop с исправлениями после тестов — отдельное условие,
если он будет включён. Ни один метод не получает эталонную декомпозицию бесплатно.

## Подготовка без API

node examples/prepare-webhook-scenario.js печатает taskId, короткий brief и хеши.
С --out /absolute/new-scenario.json создаётся эксклюзивный JSON сценария без
перезаписи. Это описание задачи/TestSpec, а не готовый skillJob для Harness.
Реализация сборки — [index.js](../../examples/webhook-scenario/index.js),
задание/README — [task.js](../../examples/webhook-scenario/task.js).

Модельный prompt использует краткое задание и существующие файлы, включая общий
README. Техническая JSON-обёртка ответа одинакова. Функциональная спецификация
остаётся подробной, поскольку одинаковые тесты должны иметь понятное основание.
Сокращение prompt не должно создавать скрытых ожиданий evaluator.

## До новых экспериментов

Сценарий имеет статус validation-candidate. Модельные прогоны v2 не выполнялись.
Launcher поддерживает direct-flash, direct-pro, fixed (implement → refactor),
components (design → 3 реализации → integrate → refactor) и metaaco.
Это подготовка сравнения режимов, а не завершённый семиметодный научный эксперимент.
Не использовать stock-историю автоматически по совпадающим именам навыков.
Применимость опыта должна учитывать задачу, промпты и версии интерфейсов.

Для всех пяти режимов одинаково закреплены 8192 выходных токена на вызов,
32768 на попытку, 262144 байта входа, 65536 байт артефакта, два агентных слота,
120 секунд на API-вызов и 300 секунд на попытку. Суммарный output-бюджет резервирует
полный лимит до конкурентного вызова и возвращает остаток только при полном
подтверждённом usage; неизвестное расходование удерживает резерв. Стоимостная
резервация учитывает новый max_tokens. Старые адаптеры сохраняют default 1024.
Это технические ограничения, не экспериментально найденные оптимумы.
Прогнозы сохраняются отдельно от измерений. Для научного вывода требуются несколько
независимых задач и заранее закреплённые условия, включая возможность того, что
прямой запрос снова окажется лучшим. Преимущество MetaACO не предполагается.


## Запуск и доказательства (21 ноября 2026)

По умолчанию команда ниже только локально строит план, не вызывает модель:

```sh
node examples/run-webhook-scenario.js --method metaaco --seed 7
```

`--out /absolute/new-preview.json` сохраняет preview без перезаписи. Для реального
исполнения нужны `--execute`, новый каталог `--out`, закреплённый
`--docker-image sha256:…`, явный `--budget-microunits` и DEEPSEEK_API_KEY в окружении.
Платный запуск этим изменением не выполнялся. Node ≥24.9 и установленные зависимости
обязательны; launcher ничего не устанавливает.

Каталог результата содержит manifest.json (задача, тестовые хеши, прогнозы,
план, trace поиска для MetaACO, лимиты, Docker image, версии и хеши исходников),
report.json и постоянный bank с исходами тестов, командами, артефактами,
расходами и ошибками. Расширенные промпты, сырые ответы, в том числе отклонённые,
и итоговый output-token ledger сохраняются локально как артефакты банка.
Не коммитить эти данные без проверки чувствительного содержимого.

Для нового сценария история пуста. Равные десятисекундные priors для каждого
навыка/модели не измерены и не доказывают превосходство какого-либо маршрута.
Тарифные верхние границы не равны фактическим расходам. Direct считается по
независимой correctness; отсутствие REFACTOR не выдаётся за успешный TDD.
Режимы fixed/components не получены выбором победителя на этой задаче.

Offline integration проверяет все пять режимов с синтетическими ответами,
реальными Harness/LlmRuntime и независимым evaluator. Отдельная негативная
проверка отклоняет некорректный design до запуска компонент и сохраняет ответ.
Это проверка инфраструктуры, не измерение качества DeepSeek. Полноценная
проверка Docker на Lenovo и платный пилот остаются отдельными шагами.

## Статус после инфраструктурного пилота

21 ноября 2026 на commit c02135a выполнен первый реальный пилот на Lenovo:
три API-вызова, $0.012554 расчётных расходов, Fixed прошёл GREEN/REFACTOR.
Pro/components/MetaACO остановились до API по различным причинам; обучение не
проводилось. [Полный отчёт и ограничения](webhook-pilot-results.md) дополняют
предшествующий статус подготовки; не интерпретировать его как завершённое сравнение.

## Исправления после пилота: scenario job v2

Стоимость маршрута теперь прогнозируется отдельно от резерва вызова;
консервативный резерв сохраняет API-защиту бюджета. Минимальный начальный кандидат
оценивается внутри MetaACO за одну из 100 оценок. `runScenarioTrial` возвращает
schemaVersion=2 отчёт, в том числе до создания попытки/ledger. Это предотвращает
сбой study driver на чтении отсутствующего бюджета. CLI использует новую обёртку.
Подробные контракты и ограничения — [ADR 0012](../adr/0012-scenario-budget-and-feasible-start.md).
Pro под $1 по-прежнему не исполняется: корректность денежной защиты не ослаблена.
Это подготовка нового протокола; повторных платных вызовов и обучения нет.
