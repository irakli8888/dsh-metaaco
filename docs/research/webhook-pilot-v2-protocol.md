Проверить устранение срывов инфраструктуры на пяти условиях, а не доказать
преимущество MetaACO и не обучить политику. Задача webhook-retry-v2 и её публичная
приёмка не менялись. Runtime commit fbea6c9cf14ecd71e8afbd485101a33a9a6cfd54,
archive SHA-256 29a554d4371e5e18ce43aaf1d8cf135563ead30f02764a75f54ad94cd5133f6e.
7085a8e добавляет только сведения о проверках, runtime идентичен fbea6c9.

[точный исходник](data/webhook-pilot-v2/pilot.mjs) копируется в корень архивного
исходного дерева перед исполнением.

Используются scenario job v2, отдельные неизмеренные forecasts, opt-in начальный
кандидат MetaACO внутри общего лимита 100 и runScenarioTrial schemaVersion=2
([ADR 0012](../adr/0012-scenario-budget-and-feasible-start.md)). Ни результаты

## Условия, зафиксированные до исходов

Seed 7, ровно одна попытка каждого условия в порядке:

1. Direct Flash — один implement.
2. Direct Pro — один implement.
3. Fixed — implement → refactor, Flash.
4. Components — design → три независимые реализации → integrate → refactor,
   Flash. Названия файлов, приватные интерфейсы и обязанности задаёт модель
   на платном design, пересечение файлов запрещено.
5. MetaACO — поиск по общему каталогу навыков и Flash/Pro с пустой историей.

До paid dispatch preflight при бюджете $2 построил все пять планов без ошибок.
Предварительный MetaACO выбрал implement → refactor, Flash, как и fixed. Это
известно заранее и не является доказательством эффекта феромонов либо обучения.
Нельзя вручную заменить этот маршрут ради более сложной демонстрации.
Перед каждой реальной попыткой план строится повторно с оставшимся бюджетом;
это может изменить доступность модели, поэтому фактический manifest — источник
истины, а preflight не выдаётся за безусловно замороженное решение.

Приоритет — независимая acceptance correctness, TDD compliance хранится отдельно.
Одинаковые 12 target и 2 regression tests. Direct без REFACTOR может иметь
correctness=passed и state=inconclusive, что не считается полным TDD success.
Все ошибки до API, ошибки контракта, assertion failures, timeout, отмены и
неопределённые расходы сохраняются отдельно. Платных повторов и автоматического
возобновления серии нет; протокол не меняется по промежуточным исходам.

## Лимиты и отчётность

До $2 суммарно на серию. Следующая попытка получает остаток после spent + held
предыдущих. Неполный usage удерживает резерв, отсутствующий accounting прекращает
дальнейшее исполнение. Предшествующий runtime отказ может иметь подтверждённый
ноль расходов без ledger; драйвер читает report.accounting, не пытается открыть
несуществующий бюджет. Различающиеся остаточные лимиты препятствуют строгому
сравнению методов; это инфраструктурный пилот.
