## Что именно научилась учитывать система

Перед каждой попыткой история текущей задачи имела ровно 0 → 1 → 2 → 3
завершённых исхода. Из sealed snapshot восстановлены qualityEvidence и warmStartChoices;
они точно совпали с решением, сохранённым до dispatch. Утечки будущего,
другого seed или другой задачи не обнаружены. Измеренные время/стоимость сохранены
отдельно: их прогнозные priors в этой серии не обучались.

Конкретный пример — **очередь, seed 11**:

1. Раунд 0: implement на Pro → refactor на Flash; GREEN не пройден.
2. Раунд 1: design на Flash → три component implement на Flash → integrate на Pro
   → refactor на Flash; полный TDD пройден. Структурное условие было задано протоколом.
3. Раунды 2 и 3: ограничения layout/model сняты. Положительно наблюдённый компонентный
   маршрут возвращён как warm seed и оценён внутри настоящей колонии в общем лимите
   100 оценок. MetaACO выбрал его и оба раза получил полный TDD.

Другой пример — cache seed 7: после двух неуспехов в раунде 2 найден маршрут
implement Flash → review Pro → refactor Pro; он прошёл и повторился успешно
в раунде 3. Однако cache seed 11 повторил ранее успешный маршрут и провалился.
История даёт оценку надёжности, не гарантию успеха.

После завершения выполнен **бесплатный механизм-аудит**: для тех же 12 задач/seed
раундов 2/3 локальный поиск повторён без quality history и memory seed при прежних
ресурсах и solver seed. В **8 из 12** случаев выбран другой маршрут. Это свидетельство
влияния памяти на выбор в данной серии. Альтернативные маршруты через API не
исполнялись: их correctness/time/cost неизвестны. Это не outcome baseline,
не доказательство причинного выигрыша и не сравнение семи методов.

Обучалась статистика надёжности точного маршрута skill/model/dependencies на той же
задаче. Веса Flash/Pro, классификатор и перенос опыта между задачами не обучались.
Феромоны/элитный архив участвуют в каждом локальном поиске; постоянная история
Bank передаётся между поисками отдельно. Полный перебор пространства не выполнялся,
глобальная оптимальность и преимущество над baseline не установлены.

Сырые модельные ответы в Git не добавлялись.

  Использовать Node с поддержкой node:sqlite. Времена нового search могут различаться.

Аудит проверил SHA-256/размеры всех **522** уникальных артефактов, **75** нормализаций
без изменения программного source, точный pinned README, суммы **76** settlement,

seed содержит 12 записей, по 4 на задачу. Это сохранённые учебные данные,
**не frozen held-out оценка**.

Перед платной серией прошли 185 unit, 41 integration локально (1 Docker skipped),
36 Python локально (включая один незакоммиченный тест владельца). Чистая ревизия
на Lenovo: 35 Python, 6 Node-проверок с 8 synthetic online attempts через Docker,
калибровка трёх задач baseline/RED/GREEN/REFACTOR. Последующая работа меняет только
исследовательские документы/данные; проверки provenance, сумм и ссылок выполняются
повторно. Платных повторов для отчёта не было.

Следующий научный этап — заранее определить новые задачи и отдельно проверить
эксплуатацию замороженного банка против baseline с учётом стоимости этой учебной

для такого переноса сначала нужен явный проверяемый контракт признаков/совместимости.
