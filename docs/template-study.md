# Пилот выбора шаблона

Шесть задач и закреплённые тесты определены в
[template-study-tasks.js](../examples/template-study-tasks.js).
Учебные задачи: пагинация, резервирование товара, экспорт заказов.
Отложенные задачи: диапазон дат, отмена резерва, импорт контактов.

Обеим стратегиям передаётся один исходный снимок. Регрессия проверяет
сохранение version(). RED должен содержать ровно ожидаемые падения
проверок. Контрольные реализации хранятся в test/experiments и используются только
для проверки тестов. Baseline, RED и GREEN прошли для всех шести задач
локально и на Lenovo с закреплённым Docker-образом Node 24.

Протокол следующего этапа: запустить оба шаблона на каждой учебной задаче,
заморозить снимок Feedback, затем сравнить fixed, прогноз MetaACO и contextual
UCB на отложенных задачах. Для сравнения закрепить одну модель, лимиты и
порядок режимов. Учесть все попытки и рассчитанные расходы, включая ошибки.
Отложенные задачи не входят в историю обучения.

## Первый кейс из репозитория

[pricing-study-task.js](../examples/pricing-study-task.js) извлекает модуль расчёта
расходов и его зависимости из коммита 9d485e7. Задание — добавить диапазон
стоимости при известном и неизвестном числе токенов. Закреплённые проверки
покрывают известную стоимость, ограниченный диапазон и неизвестную верхнюю
границу. Регрессия проверяет существующий API calculateCost.

Параметр editablePaths применяет возвращённый файл к закреплённому снимку,
отклоняет остальные пути и передаёт полный снимок Evaluator. Исходный код и требования доступны агенту, контрольные тесты
остаются только в среде проверки. Для прогона нужен Git checkout с базовым
коммитом, поскольку экспорт исходного дерева не содержит историю Git.

## Сравнение двух замороженных снимков

`node examples/compare-pricing-feedback.js BANK_DIR SUMMARY_JSON` читает банк
успешной пары pricing-study-paired-v5 и создаёт два замороженных снимка
для event-range с одинаковой политикой и порогом времени. В одном снимке две
проверенные учебные попытки, в другом история пуста. Скрипт записывает снимки
в банк, выдаёт оценки UCB и не запускает агентов.

На Lenovo оба режима выбрали contract-v1 версии 4. Оценки обоих шаблонов
равны внутри каждого режима: 0,346410 без истории и 0,782843 с историей.
В данной политике качество имеет вес 1, время и стоимость имеют вес 0.
Обе учебные попытки получили награду 1, поэтому выбор определило правило
разрешения равенства. Это проверка выбора, без прогона отложенной задачи.

Повтор с весами 0,60 / 0,25 / 0,15: обе учебные записи исключены из
расчёта награды с причиной cost-unavailable. Расходы адаптера сохранены,
но итоговые метрики не подтверждают полноту охвата; поле полной стоимости
равно null. Оба режима выбрали contract-v1. Дополнительная проверка с
весами качества 0,60 и времени 0,40 дала contract-v1 без истории и direct-v1
с историей. При нормировке времени 120 с награды составили 0,958234 и 0,978269
соответственно. Это результат выбора на отложенном задании без его исполнения.

Новые прогоны pricing study явно заявляют `guardedCallsOnly`: все запросы
этого runtime идут через один бюджетный адаптер. Полнота подтверждается только
при завершённом исполнении и совпадении идентификаторов, валют и сумм каждого
вызова со всеми журналами бюджета попытки. Старые записи неизменяемы.
Интеграционный тест с подставным API проверяет, что обе успешные попытки
получают награды с ненулевым весом стоимости в новом замороженном снимке.
