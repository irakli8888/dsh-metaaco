# Ресурсная модель агентных задач

Вход `--problem` описывает задачи непосредственно, без PSPLIB. Он преобразуется
в настоящую модель `RcpspInstance` внешнего Python MetaACO; расписание строит
настоящий `ColonyManager`. Алгоритм не заменяется и не копируется.

## Что является ресурсом и целью

Единственный ресурс этой версии — **слот прямого дочернего агента одного запуска**.
Каждая задача занимает ровно один слот от начала до завершения. Ёмкость задаёт
`maxConcurrentAgents`. Это не число муравьёв, колоний или модельных запросов.
Вложенная делегация, независимые параллельные запуски, CPU, память и ресурсы
инструментов в этот лимит не входят. Ограничения вложенной делегации задаются профилем Harness.

`estimatedDurationSeconds` — положительная целочисленная оценка пользователя,
а не результат измерения LLM. Пока нет истории, её задают вручную. Зависимости
описывают необходимость завершения предшественников, но не передачу их ответов.

Успешный путь муравья — допустимый порядок всех работ. Реальный генератор MetaACO
строит расписание с соблюдением зависимостей и доступных слотов. Цель — **минимум
расчётного makespan** (завершения всех работ). Качество ответов, прохождение тестов
продукта и стоимость API в награду не входят. Оценки времени не являются таймаутами
или ограничением расходов; фактическое выполнение может длиться дольше.

## Входной JSON v1

См. готовый `examples/agent-tasks.json`. Небольшой пример:

```json
{
  "version": 1,
  "maxConcurrentAgents": 2,
  "tasks": [
    { "id": "inspect-code", "prompt": "Inspect code", "estimatedDurationSeconds": 30, "dependsOn": [] },
    { "id": "inspect-tests", "prompt": "Inspect tests", "estimatedDurationSeconds": 20, "dependsOn": [] },
    { "id": "review", "prompt": "Review current project files", "estimatedDurationSeconds": 10,
      "dependsOn": ["inspect-code", "inspect-tests"] }
  ]
}
```

Все поля обязательны; неизвестные поля отклоняются. Идентификаторы — уникальные
строки kebab-case. Ссылки должны вести на существующие задачи без самоссылок,
повторов и циклов. Длительности и число слотов — положительные целые числа в
безопасном диапазоне JSON/JavaScript; сумма длительностей также должна быть
безопасным целым. Нулевые длительности в агентном формате запрещены.
Оценки должны быть умеренными: внешний SGS использует временную сетку и его
потребление памяти растёт с суммой длительностей.

```sh
python3 -B python/metaaco_plan.py --source /path/to/metaACOwithCodex \
  --problem examples/agent-tasks.json > plan.json
```

Команда выполняет только поиск расписания. Бюджет: 100 оценок, до 20 итераций,
5 муравьёв на итерацию; seed по умолчанию 42. `--execution serial-order` включает
последовательное исполнение; по умолчанию используется `start-groups`.
`--instance instance.sm --tasks tasks.json` сохраняет прежний PSPLIB-режим.
Смешивать его с `--problem` нельзя. При отсутствии настоящего Python-кода команда
завершается ошибкой без подставного решателя. Проверяйте код завершения перед
использованием выходного файла.

## Выходной план v2

Агентный режим выдаёт новый envelope v2 с тем же `workflow`, что в плане v1,
и двумя обязательными полями:

```json
{
  "resources": { "agentSlots": 2 },
  "estimates": {
    "objective": "makespan",
    "durationUnit": "seconds",
    "scheduleMakespan": 40,
    "executionMakespan": 40
  }
}
```

Это фрагмент метаданных, а не полный исполняемый план. Полные поля:
`version: 2`, `planner: "python-metaaco"`, `execution`, `workflow`, `resources`, `estimates`.
Входная версия JSON задачи и версия выходного плана — разные контракты.
PSPLIB-режим продолжает выдавать план v1; он не приписывает абстрактным ресурсам
PSPLIB значение слотов агентов.

- `scheduleMakespan` — цель, которую минимизирует MetaACO по введённым оценкам.
- `executionMakespan` — сумма максимальных длительностей групп Harness. Это
  оценка после преобразования расписания, при достаточном лимите Harness и без
  накладных расходов. MetaACO пока не оптимизирует эту величину непосредственно.

Например, если `review` зависит только от `inspect-tests`, MetaACO может получить
30 секунд: проверка начинается на 20-й секунде, пока анализ кода ещё идёт.
Группы Harness `[inspect-code, inspect-tests] → [review]` дадут оценку 40 секунд.
При одном слоте исходный пример даст 60 секунд. Все эти числа — оценки,
не измеренные времена и не обещание результата оптимизации для любой задачи.

`validatePlan()` поддерживает обе выходные версии. Для v2 он проверяет число детей
в каждой группе против `agentSlots` и валидирует метаданные. Из-за барьеров и
ограниченного размера групп один workflow не запускает больше прямых детей
одновременно, чем допускает план, даже если лимит Harness выше. Более низкий лимит
Harness уменьшит параллельность и может увеличить время исполнения.

JavaScript не пересчитывает RCPSP и не доказывает правильность переданных оценок:
принимайте JSON от доверенного адаптера. `validatePlan()` возвращает снимок
`workflow`, `count`, а для v2 также `resources` и `estimates`, пригодный для preview.
`runPlannedWorkflow()` по-прежнему требует отдельного `allowLlm: true` для запуска.
Модельные вызовы при реальном провайдере могут быть платными.

## Проверка всего пути без модели

```sh
pnpm test
METAACO_SOURCE=/path/to/metaACOwithCodex pnpm test:integration
METAACO_SOURCE=/path/to/metaACOwithCodex python3 -B -m unittest discover -s python -v
```

Интеграционный сценарий `agent-problem` запускает Python CLI с настоящим MetaACO,
читает JSON v2 и исполняет его в настоящем Harness 0.2.1-rc.2 с офлайн-провайдером.
Harness в тесте допускает четыре одновременных агента, план — только два;
тест проверяет, что реально активны максимум два и зависимая задача ждёт их завершения.
Без `METAACO_SOURCE` этот сценарий и Python-тесты явно пропускаются.
Для другого Python можно задать `METAACO_PYTHON` в JavaScript-тесте.
