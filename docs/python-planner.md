# Python MetaACO → JSON → Harness

Планирование и исполнение разделены: внешний Python MetaACO вычисляет порядок RCPSP,
адаптер выдаёт JSON, Harness исполняет доверенный скрипт плагина с этим JSON как данными.
Адаптер не содержит собственного ACO и никогда не подменяет отсутствующий алгоритм.

## Внешний Python-код

Нужен каталог с `rcpsp/core.py` и `rcpsp/metaACO.py`, предоставляющими
`load_psplib_instance`, `validate_schedule`, `validate_order`, `solve_rcpsp_psplib`.
Локально проверен настоящий код проекта `metaACOwithCodex` с этими интерфейсами.
Он не скопирован в npm-пакет и не скачивается автоматически; версия внешнего Python-кода
не закреплена этим репозиторием. Если модуль недоступен или интерфейс несовместим,
построение завершается ошибкой. Для воспроизводимости фиксируйте ревизию Python-проекта отдельно.
`--source` должен указывать на доверенный код: его импорт выполняет Python.

Вход: PSPLIB-файл и JSON-объект `tasks.json`. Ключи — **нулевые индексы** работ после
загрузки PSPLIB, значения — `{ "id": "research", "prompt": "Исследовать задачу" }`.
Каждая работа с положительной длительностью должна иметь ровно одно соответствие;
нулевые работы считаются фиктивными и не исполняются. Задачи нулевой длительности
с полезной работой этим контрактом не поддерживаются.

```sh
python3 -B python/metaaco_plan.py --source /path/to/metaACOwithCodex \
  --instance /path/to/instance.sm --tasks tasks.json > plan.json
```

Это только вычисление расписания, без LLM. Бюджет адаптера: 20 итераций,
5 муравьёв на итерацию, максимум 100 оценок, seed 42 (можно изменить `--seed`).
Диагностика Python идёт в stderr, stdout содержит только JSON. При ошибке не используйте
частичный или пустой файл: проверяйте код завершения команды.

## Контракт v1

```json
{
  "version": 1,
  "planner": "python-metaaco",
  "execution": "serial-order",
  "workflow": {
    "name": "metaaco-plan",
    "description": "External MetaACO precedence-feasible order",
    "stages": [
      { "title": "Job 1", "agents": [{ "id": "research", "prompt": "Исследовать задачу" }] }
    ]
  }
}
```

`validatePlan()` — исполняемая спецификация: неизвестные поля, версии, режимы,
дублирующиеся id/title, пустые строки и больше одного ребёнка на стадию запрещены.
Python проверяет допустимость расписания и порядка настоящими валидаторами MetaACO.
JavaScript проверяет структуру и делает снимок данных. Поле `planner` — метка протокола,
а не криптографическое доказательство происхождения: принимайте планы из доверенного источника.

**Ограничение:** это последовательная проекция найденного допустимого порядка,
а не точное исполнение расписания RCPSP. Времена старта, makespan и ресурсная
параллельность не переносятся; выигрыш оптимизатора по makespan не обещается.
Последовательное исполнение сохраняет зависимости и не превышает ресурсы валидной
однорежимной RCPSP-задачи при исходных требованиях ресурсов. Реальные длительности
LLM-запросов и затраты API адаптер не моделирует. Результаты между задачами автоматически
не передаются; обратной связи для перепланирования нет.

## Исполнение в существующем Harness

```js
import { readFile } from 'node:fs/promises'
import { validatePlan, runPlannedWorkflow } from 'dsh-metaaco/planner'

const plan = JSON.parse(await readFile('plan.json', 'utf8'))
const preview = validatePlan(plan) // ни Python, ни engine, ни LLM не запускаются
// После отдельного разрешения пользователя на реальные дочерние LLM-запросы:
const result = await runPlannedWorkflow(ctx, parent, plan, {
  allowLlm: true,
  subagentProvider: 'spawn',
  signal,
})
```

`ctx` и живой `parent` предоставляет приложение Harness, как для `runWorkflow`.
`allowLlm: true` разрешает запуск и может привести к расходам у настоящего провайдера.
Без него метод завершается ошибкой до запуска engine. `signal`, отмена, ошибки и
`dispose()` используют существующий жизненный цикл Harness. Slash-команда `/metaaco`
по-прежнему принимает обычный workflow JSON; envelope `plan.json` использует новый API.
Для существующего preview через slash-команду передайте только `plan.workflow` в отдельном файле.

## Проверки без API

```sh
pnpm test
pnpm test:integration
METAACO_SOURCE=/path/to/metaACOwithCodex python3 -B -m unittest discover -s python -v
```

При отсутствии `METAACO_SOURCE` внешние Python-тесты явно пропускаются.
Они используют настоящий `ColonyManager` и небольшой RCPSP-граф, проверяют экспорт,
неверные соответствия и недопустимое расписание. JavaScript-тесты проверяют контракт,
согласие на запуск, передачу параметров, отказ и освобождение ресурсов.
Два интеграционных сценария исполняются настоящим `dsh-workflow-ptc@0.2.1-rc.2`
и PTC Node runtime с провайдером `offline`: исходный параллельный workflow и
последовательный план. Провайдер возвращает фиксированные ответы и не использует API.
Интерактивный профиль и реальные модельные запросы этими тестами не проверяются.
